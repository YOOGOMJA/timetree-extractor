## 팀 검토 (3역할, 비동기)

- **기획(PM)**: 빠진 기능/단계, 정보 충분성, 잡 정합, 시나리오 공백.
- **UX 디자이너**: 정렬·위계·밀도, 플로우·전환, 일관성, 시각 접근성.
- **개발**: 디자인 토큰 부재, 컴포넌트 추출, 구현 부채, 디자인시스템 적용 경로.

출력: 각 역할의 우선순위(P1~P3) 개선 리포트 → 본 문서 §"팀 검토 결과"에 통합.

### 기능·잡 공백 (PM 단독, 신규 가치 — 화면 골격엔 없던 것)
| # | 항목 | P | 핵심 |
| --- | --- | --- | --- |
| J1 | **캘린더별 부분 실패 = 전량 중단** | P1 | 이벤트 fetch 한 캘린더만 실패해도 성공분까지 버리고 error. 라벨은 soft-fallback인데 이벤트만 hard-fail 비대칭. no-silent-loss 정신과 충돌. → 부분 실패 수집+성공분 진행. |
| J2 | **공유 캘린더 1급화** | P1 | 차별적 **핵심 가치**인데 화면엔 평범한 체크박스로 증발. 개인/공유 구분 배지·"공유 N개 포함" 요약. |
| J3 | **로그인 만료 전용 동선** | P1 | 세션 만료가 일반 error로 뭉개짐. "다시 로그인 → 재시도" 구체 동선+TimeTree 탭 버튼. |
| J4 | **"다시 시도"=idle 리셋** | P1/P2 | 선택 캘린더·기간 소실 → setup 재입력 강요. 컨텍스트 보존 재시도. |
| J5 | **dropped 분해 + normalize 실패 카운트** | P2 | 제외 수가 "기간밖+형식+처리실패" 합산. normalize 실패 건은 어느 집계에도 안 잡히는 **silent loss 사각지대**. 분해 노출 필요. |
| J6 | **"분석" 카피·소요 기대치** | P1 | 전량 fetch·소요 시간 무게가 카피에 없음. "일정 수집·분석(시간 걸릴 수 있어요)". |
| J7 | **재방문 경로** | P1/P2 | recent 기록은 재방문 전제인데 "이어가기" 동선 없음. recent 클릭→설정 프리필. |
| J8 | **import 성공 확인/FAQ** | P2 | 잡의 진짜 끝(실제 들어갔나) 확인 장치 없음. guide에 검증 체크·흔한 문제 FAQ. |
| J9 | **첫 화면 로컬 전용 안심 한 줄** | P2 | "전송 안 함" 안심이 export 직전 모달까지 가야 나옴 → idle 앞단으로. |

### 충돌 조정 / 순서 결정
- **워크플로우 순서 수정**: 사용자 원안은 `HTML 목업(3) → 디자인 시스템(4)`이나, Dev·UX가 만장일치로 **"토큰 먼저"**. → **단계 3·4 병합**: 디자인 시스템(토큰+다크모드)을 **검토 반영 HTML 데모로 동시에 구현**(데모가 곧 디자인시스템 쇼케이스). 그 후 단계 5에서 실제 UI 적용.
- J1(부분 실패)·J5(silent loss)는 **로직 변경**이라 UI 재정비와 별개 트랙(코드 이슈)로 분리.

## 단계 5 = 추적 이슈 (블라인드 미적용, 검증 전제)
