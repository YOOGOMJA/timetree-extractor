# TimeTree 약관/AUP 리스크 정리 (#93)

> **법률 자문 아님.** 이 문서는 공개 배포(ADR 0006) 전 변호사 검토에 가져갈 **리스크 정리·질문 목록**이다. 최종 가부 판단은 사용자/법무의 몫이다. 근거: `docs/research/timetree-policy-and-web-research.md`(확인일 2026-05-13), TimeTree 공식 공지.

## 한 줄 결론

가장 큰 법적 리스크는 **"비공식 내부 API에 대한 자동화 접근을, 공개 배포되는 도구로 수행"**한다는 점이다. 개인이 자기 세션에서 자기 데이터를 백업하는 것과, 그걸 **공개 도구로 배포**하는 것은 리스크 수준이 다르다. 공개 제출 전 변호사 확인을 권한다.

## 사실 관계 (확인된 것)

- TimeTree **공식 Connect App / API는 2023-12-22 종료**됨. 현재 공개 developer API 없음.
- 공식 Help 기준 **일반 event export 기능 없음**(external→TimeTree import 방향만).
- 약관: 사용자가 **자기 책임으로 백업**해야 한다고 설명.
- AUP는 third-party 권리·프라이버시 침해, 과도한 네트워크/시스템 부하, 불법 접근을 금지.
- 본 확장은: 사용자가 **이미 로그인한 세션**에서 read-only로 내부 `/api/v1/...`를 호출, 단일 패스(retry/backoff 없음), 서버 전송 없음, 로컬 저장.

## 변호사에게 물을 핵심 질문 (요약)

1. 사용자 본인 세션에서의 read-only 자동 접근이 TimeTree ToS/AUP 위반인가? **공개 스토어 배포**가 그 판단을 바꾸는가?
2. 위반 소지가 있다면, **비공개(직접 설치) 배포로 한정**하면 리스크가 충분히 낮아지는가?
3. 공유 캘린더 타인 개인정보를 파일로 만들도록 돕는 것의 개발자 책임(한국 PIPA 포함) 범위는?
4. 명칭/설명의 "TimeTree" 사용이 상표 관점에서 안전한가?

## 사용자 결정 (2026-06-13) — 리스크 수용

> 변호사 clearance가 **아니다.** 프로젝트 소유자가 리스크를 인지하고 **수용**해 진행하기로 한 결정이다. 분쟁 발생 시 그때 대응한다.

| # | 결정 | 근거(사용자) |
| --- | --- | --- |
| 1 자동 접근 | **진행** | 일단 가고, 시시비비 생기면 그때 판단. |
| 2 공개 배포 | **공개 진행** | 영리 아님 — 개인 백업용. |
| 3 공유 타인정보 | **사용자 동의 책임 하에 허용** | 가족 사용 맥락. 도구는 경고+동의로 *타인 동의 확인 책임이 사용자에게 있음*을 명시(경고 카피 강화 반영). |
| 4 명칭 | **"TimeTree" 명칭 유지** | 명칭 없으면 서비스 인지 불가(호환 표기). |

영향: ADR 0006 게이팅 1·2는 **사용자 리스크 수용으로 해소**(법적 clearance 아님). 분쟁 시 0006 옵션 B(비공개 한정)/C(보류)로 후퇴 가능.

## 결정 옵션 (참고 — 변호사 자문 시)

- **A. 공개 스토어 제출 진행** — 변호사가 1·3을 충분히 낮다고 확인할 때.
- **B. 비공개/직접 설치로 한정** — 1이 공개 배포에서만 문제될 때(0006의 베타 단계 유지·확장).
- **C. 보류·범위 축소** — 1이 본질적 위반일 때(예: 내부 API 대신 다른 합법 경로 모색).

> 권고(법적 판단 아님): **공개 제출 전 위 1·3을 변호사와 확정**한다. 그 전까지는 0006의 베타(직접 설치) 단계에 머무르는 것이 안전하다.

## 게이팅 처리

- #93은 **사용자 리스크 수용 결정으로 종결**(2026-06-13). 법적 clearance가 아니라 소유자의 진행 결정이다.
- 분쟁·차단·C&D 발생 시 0006 옵션 B(비공개 한정)/C(보류)로 후퇴하는 것을 비상 계획으로 둔다.
